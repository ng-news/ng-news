Angular 22.2 — Router Resources, Error Boundaries, and Private Template Members

A steady maintenance release with three features that quietly change how you structure apps. We break down what shipped, what it means for existing codebases, and what to watch in the RFC pipeline.

ReleasesRouterTemplates
01 Router Resources 02 Error Boundaries 03 Private Template Members
01

Router Resources: data loading gets a first-class shape

The 22.2 release lands the resource-based router API that has been brewing through the RFC process since early 2026. Loaders and resolvers collapse into a single declarative unit that composes with signals, and the old callback styles get deprecated in the same train.

In practice, a route definition now carries a resource entry that owns its own cache policy and refresh behaviour — no more parallel loadChildren gymnastics for shared lookups.

02

Error Boundaries: finally, a catch-all for template errors

Error boundaries arrive as a template-level construct: wrap a subtree, declare a fallback, and template-time errors stop taking the whole view with them. The RFC thread made two things explicit — lifecycle hooks of the failing component still run, and boundary errors never cross lazy-route module boundaries.

03

Private Template Members: encapsulation for the template

The third feature is smaller but cuts deep: template members can now be marked private, keeping them out of the component's public API surface. Library authors get the encapsulation guarantees they've been faking with naming conventions since Angular 2.

The trade-off flagged in the RFC thread: private members are still part of the compiled template contract, so cross-boundary template composition patterns need a rework — the migration guide in the issue walks through the three affected patterns.
